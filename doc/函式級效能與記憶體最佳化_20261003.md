本輪以第一輪最佳化完成後的來源快照為基準，新舊版本均採 release `-O -whole-module-optimization`，沒有把上一輪的編譯器最佳化收益重複計算。交錯量測中，21 組逐鍵混打由 9.03 秒降至 7.92 秒，耗時減少 12.3%；中文分詞探針的峰值 RSS 由 352.81 MiB 降至 329.75 MiB。整段混打的峰值 RSS 則由 446.30 MiB 增至 456.98 MiB，增加 2.4%。因此，本輪有函式暫存與特定工作負載的記憶體改善，不能宣稱整個 App 的峰值記憶體全面下降。

函式及資料存取的主要變更如下：

| 範圍／函式 | 修改及效果 |
| --- | --- |
| `UnifiedCandidateRanker.ranked`、`CandidateTopK` | 以最差候選置頂的有界 heap 選取前 K 筆，只排序保留的 K 筆。當 K 小於 N，選取為 O(N log K)（K=1 時為 O(N)），候選選取器暫存為 O(K)；原有批次分數陣列仍為 O(N)。要求全部候選時沿用完整排序。保留分數、baseRank、原輸入順序的平手規則，過濾非有限分數。 |
| `CoreMLCandidateRanker.ranked` | 無模型時直接使用上述選取器；純 AI 與混合模式亦共用有界選取。混合模式保留理論分數上界及嚴格小於才停止的判斷。 |
| `ReadingWalker.scoredEdges`、`resolveWalk`、`scorePath` | 共用逐邊產生器，即時分詞直接消費候選邊；離線 API 仍可取得完整陣列。DP 分數、片段數及回溯資料按實際缺口長度配置，左文以最多三筆的陣列更新。 |
| `MixedCompositionResolver.strongestExactEnglishCoverages` | 改為由尾端向前的 DP，保存分數、覆蓋長度、片段數及選取的邊，最後回溯一次。移除遞迴與每個狀態的完整路徑陣列；DP 本身的最壞暫存由 O(n²) 降至 O(n)，候選邊集合另外計算。 |
| `UnifiedCompositionEngine.mergeSpanCoverages` | 缺口求解只保存分數與下一條邊，最後建立文字及覆蓋範圍；維持原本浮點相加順序與平手選擇。相同地減少 DP 完整路徑的重複保存。 |
| `UnifiedCompositionEngine.spanCoverages` | 使用雙層 Optional 正確保存「查無提交文字」，避免 nil 被視為移除字典項目而重複求解。 |
| `CandidateScoringInput.make` | 共用局部上下文建構，直接產生候選單位；移除 matches → surfaces → units → copied units 的中間陣列。從左文尾端只取得最後三個非空片段，保留舊模型座標。 |
| `RankingFeatureEncoder` | 預留 88 維結果容量，直接追加 one-hot 特徵；合併統計掃描、重用字串與聲調字元集，避免建立交集 Set 及多份字元陣列。 |
| `ListwiseFeatureEncoder.encode` | 同組候選只計算一次前後文及雜湊，直接填入固定大小張量；候選 scalar 數、漢字數及 Latin 數在同一次掃描中計算。此編碼器屬離線／實驗模型路徑，目前即時 listwise 排序仍關閉。 |
| `SentenceFeatureEncoder.encode` | 以一次片段掃描計算長度、詞頻及相鄰統計，移除三組中間陣列；保留 24 維順序及浮點加總順序。量測耗時近似持平。 |
| `HeuristicCandidateRanker.scores`、`score` | 偏好資料直接彙整至字典，重用中文字數與跨度是否相符的判斷。 |
| `UserFrequencyStore.record`、`frequency`、`frequencyMap` | 透過巢狀字典的可變存取器更新，避免每次選字複製整個語言詞頻表；單一候選查詢直接掃描該讀音資料。鎖外只保留該讀音陣列，保留重複資料取最大值、更新第一筆及既有持久化鎖定規則。 |
| `PersonalVocabularyStore.batch`、`candidates` | 已驗證同批身分不重複後，一次移除所有被修改詞彙，再依原順序加入。刪除階段由 O(詞彙數 × 變更數) 改為 O(詞彙數 + 變更數) 次身分查詢；候選合併避免先串接整份陣列。 |
| `EnglishLexiconStore` 查詢、英中 `buildReverseLexicon` | 直接檢查精確索引是否存在，按需從編號取得詞條；反查表直接更新對應陣列，避免反覆複製。 |
| `LexiconStore.compositionMatches` | 同一次遍歷檢查補調相容性與計算距離，移除正規化結果陣列及差異過濾陣列。 |
| `MixedInputBoundaryResolver` | 以 String 字元索引掃描分界，保留組合字元行為；重用整詞判定，只在英文前綴合格後建立後綴。已有組字狀態時直接回傳是否能形成主語言內容。 |
| `SessionCtl.inverseBopomofoMap`、`keySequence`、`keyTokens`、`mapKeySequence` | 不可變反查表只建立一次；鍵序轉換直接累積結果，遇到無法對應的按鍵立即結束，減少巢狀 map／joined 陣列。 |
| `UnifiedCompositionState.sourceInput`、`sourceInputs`、`inputSpan`、`attachSources` | 一次畫面更新共用來源資料及字元前綴和；候選起點由重掃前段改為查表，讀音驗證及 raw 字串仍依實際跨度計算。空字串不建立反查資料；單側讀音與鎖定集合直接沿用既有值。 |
| 注音引擎 `feed`、`stabilizePrefixBeforeAppend`、`baseDisplayedSegments` | 小寫化只做一次，直接逐字處理；每次操作只讀一次窗口設定，下一次操作仍會取得更新後設定；重用合併讀音。 |
| 顯示、游標、資料工具 | 候選計數與索引直接使用 entries；繪圖屬性按一次 draw 共用，寬度直接歸約；游標保留 UTF-16 與完整字元邊界。資料對齊使用前綴比對，避免反覆建立候選字元陣列。 |
