# 候選與分詞計分

組字、候選窗及 MCP 預覽共用候選計分。候選召回僅合併系統與個人詞彙，不按個人 priority 預先置頂；個人偏好只在計分時加入一次。

## 同音候選

`HeuristicCandidateRanker` 統一計算以下項目：

- 原始候選順位：每名扣 40 分，個人偏好不改寫這個順位。
- 個人選取紀錄：`min(log2(次數 + 1) × 40, 400)`；沒有紀錄為 0。
- 個人 priority：直接加入設定值，不累加、不改動實際詞頻。
- 精確讀音的多字詞語料：`min(log10(詞頻 + 1) × 120, 500) × 音節數`。詞與音節長度須一致；按讀音與詞形查詢，避免跨讀音借用詞頻。

語料項按涵蓋音節數計算，避免相同語料強度因切成更多詞而重複領取固定獎勵。這些係數是目前策略，不是準確率保證。

Core ML 的單筆與批次介面使用相同混分公式。傳統優先模式沿用有界 AI 殘差，預設每個候選介於 -56 與 +56 分；移除額外的首選 60 分獎勵。模型不可用時回退共用規則分數。

## 分詞

`ReadingWalker.scoredEdges` 統一建立組字候選與分數：

- 多音節跨度必須是詞庫或個人詞彙中的完整詞，且一字對應一音節。
- 最長八個音節；全部合法候選先評分，不先截取原始前八名。
- 路徑加分為 `1800 × (音節數 − 1)`，表示合併的邊界數；沒有每詞 5000／12000 分獎勵。
- 移除僅憑功能字或時態字身分給予的固定加分，以及同音功能字造成的邊界扣分。
- 無可用單音節候選時保留退避路徑，分數為 -4000。

候選窗可以帶入實際左側上下文，組字搜尋使用右側音節；公式一致不代表上下文不同時排序必須相同。顯示層仍將目前正文放在候選第零項，避免單純移動游標就改寫正文。MCP 預覽沒有完整句子上下文，不代表實際句子評估。
