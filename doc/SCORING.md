# 候選與分詞計分

組字、候選窗及 MCP 預覽共用候選計分。候選召回僅合併系統與個人詞彙，不按個人 priority 預先置頂；個人偏好只在計分時加入一次。

## 讀音資格

精確查詢不跨聲調或以鄰鍵補字，沒有調號視為第一聲；尚未完成的音節由組字狀態處理。來源覆寫必須符合原始詞庫的整詞讀音，或能由每個字的正式讀音組成，才可參與候選排序。整詞來源保留既有異讀與變調，不能用去調別名冒充精確命中。驗證使用未混入覆寫的原始資料，避免覆寫自行證明合法。

反查、前綴與中英辨識也只合併驗證後的覆寫。一般讀音提交與組字共用分詞排序，不另行直接取覆寫首選；數字保護維持獨立處理。個人詞彙仍由使用者或獲授權的 Agent 明確設定。

## 省略聲調整詞補救

`compositionMatches` 先查精確候選；沒有精確整詞時，二至八個音節才可查相同聲韻母的詞庫讀音。每一音節及明確輸入的聲調必須相符，只能補足無調號音節；單字查詢、反查及前綴查詢仍維持精確規則。補救索引隸屬詞庫實例，首次使用時依系統詞庫建立，不逐次枚舉所有聲調排列。

補救詞保留原始 `readingOrToken`、替換讀音及來源按鍵，另以 `lexiconReading` 讀取該詞正式讀音的語料證據。每個補調音節扣 120 分；另扣 `500 × (音節數 − 1) / sqrt(語料權重 + 1)`，讓低頻詞承擔較高的不確定性。這個上界與分詞結合度一致，避免少見詞僅因字間結合度高便取代正常單字。精確候選不扣這兩項；個人詞頻與 priority 仍以原始讀音計算。

先以精確候選解碼，保留所得多音節詞；只有連續單字區段再比較補調候選及原單字路徑。仍以總分決定是否合詞，不保證每個未知組合都強迫替換。組字與選字共用召回和評分，人工確認的詞段保持鎖定。新補救限於索引已有的系統詞讀音；完全新增且無系統讀音的個人詞仍使用精確查詢。

## 個人詞頻與快取

`LexiconStore` 的候選快取隸屬各詞庫實例，最多保留 512 筆；不同覆寫表不共用查詢結果。個人詞彙在讀取基礎快取後即時合併，避免保存過期的個人候選。

`UserFrequencyStore` 對同語言、讀音與詞形累積明確選字次數。記錄與延遲保存工作共用鎖，磁碟寫入另行序列化；成功保存且資料版本未變動時才清除待保存標記。失敗時保留標記供後續保存重試，寫入期間新增的選字也不會被舊快照標記為已保存。

## 同音候選

`HeuristicCandidateRanker` 統一計算以下項目：

- 原始候選順位：`min(log2(從零起算的順位 + 1) × 40, 240)`，個人偏好不改寫這個順位。名次成本有上限，避免後段候選及新增個人詞被無限扣分。
- 個人選取紀錄：`min(log2(次數 + 1) × 40, 400)`；沒有紀錄為 0。
- 個人 priority：直接加入設定值，不累加、不改動實際詞頻。
- 精確讀音的多字詞語料：`min(log10(詞頻 + 1) × 120, 500) × 音節數`。詞與音節長度須一致；按讀音與詞形查詢，避免跨讀音借用詞頻。

語料項按涵蓋音節數計算，避免相同語料強度因切成更多詞而重複領取固定獎勵。這些係數是目前策略，不是準確率保證。

不同讀音跨度之間另做分數基準校正。對每個讀音及字數，取語料權重最高的詞作參考：以該詞的權重占比，對比各字獨立出現的背景占比，計算 `120 × ln(P(參考詞) / ∏P(字))`。背景統計來自現有詞庫內二至八字詞，每個詞形只取最大權重一次，不因異讀重複累計。這是詞庫衍生的結合度估計，不是句子語意模型或真實語料機率保證。

結合度保留負值，限制在每個詞內邊界 ±500 分，再乘 `權重 / (權重 + 1)` 降低低頻證據的影響。以此取代參考詞原有的絕對語料基準：同讀音、同跨度的每個候選一律加上「結合度分數 − 參考詞原語料分數」。因此同音候選之間的分差不變，個人使用紀錄與 priority 仍只加入一次；改變的是不同分詞範圍之間的比較。缺少語料參考的跨度不套用此校正。

Core ML 的單筆與批次介面使用相同混分公式。傳統優先模式使用有界 AI 殘差，每個候選介於 -56 與 +56 分；移除額外的首選 60 分獎勵。環境變數可降低模型尺度，上限為 160，經模式係數 0.35 後即為 56。模型不可用時回退共用規則分數，批次共用詞頻查詢；單筆與批次分數及排序保持一致。

需要前 K 名時，先計算所有候選的基礎分數。只有候選的基礎分數加上 AI 理論上界仍嚴格低於目前第 K 名，才可省略推論；平手仍評分。這與先截取原始前幾名不同。模型實例另快取最多 512 組原始預測，不快取使用紀錄或 priority 混入後的分數。

## 分詞

`ReadingWalker.scoredEdges` 統一建立組字候選與分數：

- 多音節跨度必須是完整來源詞條，且一字對應一音節；精確候選接受 phrase_map、common_map、既有覆寫及個人詞彙，不只限定 phrase_map。沒有精確整詞時才依上述省略聲調規則補救，不以任意近音或鄰鍵退避。
- 最長八個音節；全部合法候選先評分，不先截取原始前八名。
- 分詞路徑直接加總經跨度基準校正的候選分數，不再加入每合併邊界 1800 分或每詞 5000／12000 分獎勵。低頻字串不會僅因詞庫收錄就獲得正向合詞獎勵。只有總分完全相同時，才以較少詞段打破平手。
- 移除僅憑功能字或時態字身分給予的固定加分，以及同音功能字造成的邊界扣分。
- 無可用單音節候選時才額外查詢回退候選，保留分數為 -4000 的退避路徑，避免在正常跨度重複查詢。

自動組字採兩個步驟：先用明確注入的 pathRanker（預設為規則評分）決定分詞範圍，再由上下文 ranker 固定各範圍，依序用已選出的左文進行同讀音 AI 排序。產生不同的新路徑後，必須將原路徑與新路徑依各自前文重算整句分數；只有新路徑嚴格較高才採用，平手、降低或驗證失敗均保留原路徑。這提供相對於原路徑的整句分數保障，不代表所有可能分詞的全域最佳解。

`CandidateScoringInput` 統一候選身分及模型座標：前後各最多三個音節、左文最多三個片段，保留片段邊界，spanStart 相對於該局部視窗。組字與候選窗共用此入口，避免複製完整後文。沒有合法候選的跨度不建立模型輸入。取得左文時，完整涵蓋的英文或多字候選保留全部文字；游標位於詞內時才取已涵蓋的前綴，不以組字單位數截短完整英文詞。

模型格式由 Core ML 自訂 metadata 的 `unifyime.feature_contract` 指定。`bounded_segments_v2` 使用上述局部座標；`legacy_segments_v1` 使用舊式片段前文、整句位置及最多六個後文音節。未標記的既有模型採明確的 legacy 相容模式，診斷狀態會標示 metadata_missing；未知格式不載入並回退規則。舊格式只額外保存位置、整句長度及必要的六個音節，不複製完整後文，也不把多個前文片段壓成一個字串。

候選窗的整詞與詞內單字先依各自讀音、長度、位置及來源順位評分，再以候選身分合併；不以整詞讀音查單字偏好。override 僅作原始來源順位，排序後不再搬動其他候選。顯示層仍將目前正文放在候選第零項，避免單純移動游標就改寫正文。

固定路徑的上下文分數由 `ReadingWalker.scorePath` 計算，並核對讀音、候選合法性與完整覆蓋範圍。MCP 預覽沒有完整句子上下文，也不代表整句評估。
