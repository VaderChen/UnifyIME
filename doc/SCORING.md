# 候選與分詞計分

組字、候選窗及 MCP 預覽共用候選計分。候選召回僅合併系統與個人詞彙，不按個人 priority 預先置頂；個人偏好只在計分時加入一次。

## 同音候選

`HeuristicCandidateRanker` 統一計算以下項目：

- 原始候選順位：`min(log2(從零起算的順位 + 1) × 40, 240)`，個人偏好不改寫這個順位。名次成本有上限，避免後段候選及新增個人詞被無限扣分。
- 個人選取紀錄：`min(log2(次數 + 1) × 40, 400)`；沒有紀錄為 0。
- 個人 priority：直接加入設定值，不累加、不改動實際詞頻。
- 精確讀音的多字詞語料：`min(log10(詞頻 + 1) × 120, 500) × 音節數`。詞與音節長度須一致；按讀音與詞形查詢，避免跨讀音借用詞頻。

語料項按涵蓋音節數計算，避免相同語料強度因切成更多詞而重複領取固定獎勵。這些係數是目前策略，不是準確率保證。

Core ML 的單筆與批次介面使用相同混分公式。傳統優先模式使用有界 AI 殘差，每個候選介於 -56 與 +56 分；移除額外的首選 60 分獎勵。環境變數可降低模型尺度，上限為 160，經模式係數 0.35 後即為 56。模型不可用時回退共用規則分數。

需要前 K 名時，先計算所有候選的基礎分數。只有候選的基礎分數加上 AI 理論上界仍嚴格低於目前第 K 名，才可省略推論；平手仍評分。這與先截取原始前幾名不同。模型實例另快取最多 512 組原始預測，不快取使用紀錄或 priority 混入後的分數。

## 分詞

`ReadingWalker.scoredEdges` 統一建立組字候選與分數：

- 多音節跨度必須是精確讀音下的完整來源詞條，且一字對應一音節；接受 phrase_map、common_map、既有覆寫及個人詞彙，不只限定 phrase_map。此處不使用去調或近音退避候選。
- 最長八個音節；全部合法候選先評分，不先截取原始前八名。
- 分詞路徑直接加總基礎候選分數，不再加入每合併邊界 1800 分或每詞 5000／12000 分獎勵。只有總分完全相同時，才以較少詞段打破平手。
- 移除僅憑功能字或時態字身分給予的固定加分，以及同音功能字造成的邊界扣分。
- 無可用單音節候選時保留退避路徑，分數為 -4000。

自動組字採兩個步驟：先用明確注入的 pathRanker（預設為規則評分）決定分詞範圍，再由上下文 ranker 固定各範圍，依序用已選出的左文進行同讀音 AI 排序。產生不同的新路徑後，必須將原路徑與新路徑依各自前文重算整句分數；只有新路徑嚴格較高才採用，平手、降低或驗證失敗均保留原路徑。這提供相對於原路徑的整句分數保障，不代表所有可能分詞的全域最佳解。

`CandidateScoringInput` 統一候選身分及模型座標：前後各最多三個音節、左文最多三個片段，保留片段邊界，spanStart 相對於該局部視窗。組字與候選窗共用此入口，避免複製完整後文。沒有合法候選的跨度不建立模型輸入。

模型格式由 Core ML 自訂 metadata 的 `unifyime.feature_contract` 指定。`bounded_segments_v2` 使用上述局部座標；`legacy_segments_v1` 使用舊式片段前文、整句位置及最多六個後文音節。未標記的既有模型採明確的 legacy 相容模式，診斷狀態會標示 metadata_missing；未知格式不載入並回退規則。舊格式只額外保存位置、整句長度及必要的六個音節，不複製完整後文，也不把多個前文片段壓成一個字串。

候選窗的整詞與詞內單字先依各自讀音、長度、位置及來源順位評分，再以候選身分合併；不以整詞讀音查單字偏好。override 僅作原始來源順位，排序後不再搬動其他候選。顯示層仍將目前正文放在候選第零項，避免單純移動游標就改寫正文。

固定路徑的上下文分數由 `ReadingWalker.scorePath` 計算，並核對讀音、候選合法性與完整覆蓋範圍。MCP 預覽沒有完整句子上下文，也不代表整句評估。
